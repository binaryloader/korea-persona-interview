# 백로그: v1.3.0

본 문서는 v1.2.0 출시 시점까지 본체에 들어가지 않은 백로그 항목을 모은다. 각 항목은 동기, 영향 범위, 사전 의존성을 짧게 적는다. 우선순위 결정은 v1.2.0 운영 데이터(실제 사용자 피드백, 토큰 비용 패턴, drift 비율, MCP server / MCP orchestrator 진입 분포)가 모인 뒤 다시 본다.

## 1. 외부 통합

### 1.1. FastAPI REST API

- 동기는 MCP/CLI 외에 REST API 진입을 원하는 외부 시스템(웹 대시보드, 사내 자동화 등)도 같은 application 계층을 재사용할 수 있다는 점이다
- 영향 범위는 `src/api/` 신규, 의존성 `fastapi`/`uvicorn` 추가, 인증 `X-API-Key` 헤더, 비동기 큐로 `run_batch` 백그라운드 실행이다
- 사전 의존성은 application 계층이 진입점에 독립적이라는 점으로 라운드 C1에서 확인 완료다

### 1.2. provider별 페르소나 응답 품질 검증 보고서

- 동기는 OpenAI / Anthropic / 로컬 LLM 세 경로가 활성화되었지만 페르소나 일관성과 drift 비율은 여전히 `gpt-4o-mini`로만 검증된 상태라는 점이다. 라운드 G에서 LLM-as-judge 옵션이 들어왔지만 골든 데이터셋은 아직 없다
- 영향 범위는 `tests/manual/quality_validation.py` 신규 작성으로 provider별 100명 페르소나 인터뷰와 메트릭 자동 측정을 수행하고 결과 표를 `docs/quality/{provider}_{model}.md`로 저장한다
- 사전 의존성은 골든 데이터셋 50-100개 정의다. intent 분포가 알려진 페르소나 쌍을 우선 모은다

## 2. 보안과 운영

### 2.1. 시크릿 keychain 연동

- 동기는 macOS Keychain/Linux libsecret/Windows Credential Manager에 키를 저장하면 `.env` 파일이 디스크에 평문으로 남지 않는다는 점이다
- 영향 범위는 `src/config.py` 시크릿 로더에 keyring 라이브러리 도입 또는 OS 명령 호출, README 설치 가이드다
- 사전 의존성은 keyring 라이브러리(또는 동등한 stdlib 우회)의 라이선스/취약점 점검이다

### 2.2. 진행률 + 부분 결과 streaming 저장

- 동기는 100명 배치 도중 OOM/네트워크 단절로 프로세스가 죽으면 마지막 SIGINT partial save 이후 진행분이 모두 사라진다는 점이다
- 영향 범위는 `src/batch.py` record 단위 increment append, 결과 JSON 포맷 부분 record 안전 직렬화, tqdm 자리 정합이다
- 사전 의존성은 v1.1.0 `--resume`이 들어왔으니 streaming 저장은 검증 데이터를 본 뒤 도입 가치 결정한다

## 3. 토큰 사용량 최적화

### 3.1. OpenAI Batch API offline 경로

- 동기는 100명 배치를 실시간으로 받을 필요가 없다면 OpenAI Batch API의 24시간 윈도우 전송 경로를 활용해 사용자 provider의 batch 단가 혜택을 받을 수 있다는 점이다. 단가 비교는 사용자 본인의 OpenAI 청구 페이지에서 확인한다
- 영향 범위는 `src/llm_client.py` Batch endpoint, `src/batch.py` async ↔ batch poll 흐름 분리, 결과 JSON에 `batch_job_id` 추가다
- 사전 의존성은 사용자가 비실시간 결과를 수용한다는 명시적 옵션 즉 `--batch-async` 플래그다

### 3.2. multi-model A/B 라우팅

- 동기는 같은 페르소나 샘플에 다른 모델을 돌려 응답 품질을 비교하면 모델 선택 의사결정이 빨라진다는 점이다. 라운드 G13의 `--insight-model`은 단계별 모델 분리만 지원하고 같은 단계 모델 라우팅은 별도 작업이다
- 영향 범위는 `src/batch.py` 모델 라우팅 매트릭스, 리포트의 모델별 비교 표, CLI `--model-set` 옵션이다
- 사전 의존성은 cached_tokens 처리가 모델별로 정합하다는 점으로 라운드 A에서 처리 완료다

## 4. 우선순위 가이드

본 백로그는 단순 나열이 아니다. v1.2.0 운영 데이터를 보고 아래 순서로 검토한다.

- 외부 통합 요청이 들어오면 §1.1을 우선한다
- drift 비율이 운영 데이터에서 5%를 넘으면 §1.2 골든 데이터셋부터 우선한다
- 토큰 사용량 누적이 사용자 운영 부담을 키우면 §3.1 Batch API와 §3.2 multi-model 라우팅을 우선한다
- 보안 사고/요구가 있으면 §2.1 keychain을 즉시 검토한다
